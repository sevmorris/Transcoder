Theory of Operation

Transcoder is a thin, careful layer over FFmpeg. Every conversion is one ffprobe call to learn what the file holds and one ffmpeg call to write the new one. This page explains what those calls are, why each argument is there, and what the app does around them: the queue, progress and cancellation, settings, updates, and the FFmpeg build it ships.

It assumes you know what a sample rate, a bit depth and a codec are. Names in code are the Swift types and files in the repository.

Nothing in between touches the audio. There is no filter graph of Transcoder's own, no normalisation and no dither stage beyond what FFmpeg applies when it changes the sample format. What comes out is the source, decoded and re-encoded with the settings you chose.

The source is only ever read. The output is written to a new, unused name, and removed again if the conversion fails or is cancelled.

Reading the Source

Converter.probe runs the bundled ffprobe:

ffprobe -v error -show_format -show_streams -of json <source>

SourceInfo.parse reduces the JSON to what a conversion needs:

FieldTaken from
Audio streamThe first stream whose codec_type is audio. If there is none the file fails with The file has no audio. Later audio streams — other languages, commentary — are ignored.
Channels, sample rateThat stream's channels and sample_rate (2 and 44,100 if ffprobe gives none).
DurationThe container's duration, for progress and the time limit.
CoverA video stream with the attached_pic disposition, and its codec. A real video stream is not a cover and is never mapped.
Where the tags liveMost containers keep tags at the format level. Ogg and Opus keep their Vorbis comments on the audio stream. When the container's tags are empty, once FFmpeg's own housekeeping keys (encoder, major_brand, minor_version, compatible_brands) are set aside, and the stream has tags, the stream is taken as the source of tags.

ffprobe gets 60 seconds. A file it cannot open, or JSON it cannot parse, fails with Could not read the file.

Building the Command

ArgumentBuilder is a pure function from (source, destination, format, preset, probe result) to an argument list, which is why the tests can check every format's command without running FFmpeg. The command is assembled in this order:

  1. Input and housekeeping -hide_banner -nostdin -y -i <source>, then -progress <file> -nostats so progress can be read from a file rather than parsed from stderr. -y is safe because the destination is always a name that did not exist (see The Queue).
  2. Stream mapping -map 0:<audio> for the one audio stream, plus -map 0:<cover> when there is a cover and the output format can hold it. Mapping explicitly means nothing else — video, subtitles, data streams, a second audio track — can slip through on FFmpeg's default stream selection.
  3. Metadata -map_metadata 0, or -map_metadata 0:s:<audio> when the tags live on the stream, and -map_chapters -1.
  4. Codec The encoder and its bitrate or sample format; see The Encoders.
  5. Sample rate and channels Optional -ar and -ac, only when the preset sets them. Same as source adds neither, and FFmpeg keeps the source's values unless the encoder cannot take them. Opus always gets -ar 48000, and -ac 2 when the source has more than two channels and the preset leaves channels alone.
  6. Cover Optional -c:v copy for a JPEG or PNG cover, otherwise -c:v mjpeg, and -disposition:v:0 attached_pic so players treat it as artwork rather than a one-frame video.
  7. Container Muxer options per format, then the output path.

Why These Choices

  • LAME for MP3. It is the reference MP3 encoder and the only one FFmpeg offers. ID3v2.3 rather than 2.4 because it is the version the widest range of players reads, Windows and many car stereos among them; the ID3v1 tag at the end of the file is for players older still.
  • FFmpeg's own AAC. It is the AAC encoder this build has. libfdk_aac is non-free, so it cannot be shipped in an LGPL binary, and the build is configured with --disable-autodetect, which leaves out Apple's AudioToolbox encoder along with everything else not asked for by name.
  • libopus for Opus. FFmpeg's built-in Opus encoder is still marked experimental and is weaker at low bitrates. libopus is the reference encoder, BSD-licensed, and linked statically. Opus works internally at 48 kHz, so Transcoder always resamples to it rather than write a header that claims another rate.
  • The ipod muxer for M4A. It is FFmpeg's MP4 muxer with the brand and atoms Apple's software expects, which matters for Music and iOS. +faststart moves the index to the front so the file can play before it has fully loaded.
  • 24-bit FLAC and ALAC. Neither encoder takes a packed 24-bit sample format, so 24-bit audio travels in 32-bit containers with -bits_per_raw_sample 24, which tells the encoder to write 24 significant bits.
  • 32-bit float WAV. Offered for WAV only, for handing to a DAW: a float file cannot clip, whatever gain comes later.

Sample Rates the Encoder Will Not Take

When Same as source meets an encoder that cannot accept the source's rate, FFmpeg resamples to a rate the encoder supports. MP3 is defined only up to 48 kHz, so a 96 kHz source written as MP3 at Same as source comes out at 48 kHz. That is why the MP3 sample-rate list stops at 48 kHz, and why Opus has none.

Tags and Artwork

-map_metadata copies tags across, and each muxer translates them into its own form: ID3 frames for MP3 and AIFF, iTunes atoms for M4A, Vorbis comments for FLAC and Opus, a RIFF INFO list for WAV, which has fields for only the common tags. Chapters are dropped with -map_chapters -1: few audio formats can hold them, and a chapter list copied from a video makes little sense in its audio.

Artwork is carried by OutputFormat.carriesArtwork, true for everything but two formats:

  • WAV has no standard place for a picture, so FFmpeg's WAV muxer accepts audio only.
  • Opus stores pictures as a base64 METADATA_BLOCK_PICTURE comment, which FFmpeg's Ogg muxer does not write.

For those two the cover stream is simply not mapped, so the conversion succeeds with tags and no artwork, rather than failing on a stream the muxer cannot take.

A JPEG or PNG cover is copied byte for byte. Other picture codecs (a BMP or GIF from an odd tagger, say) are re-encoded to JPEG, which every format that holds artwork accepts.

Running FFmpeg

Converter is an actor that runs one file at a time. The process itself is FFmpegProcess, a file shared byte for byte with WaxOnWaxOff and ClipHack.

Progress

FFmpeg's -progress writes key=value blocks to a temporary file as it goes. A detached task reads that file every 250 ms, takes the latest out_time_us, and divides by the duration ffprobe reported. That fraction is the row's progress bar. A source with no known duration has no bar to fill; it shows done when it is done. The progress file is deleted afterwards.

Time Limit

Each run may take max(600 s, 4 × duration). That is generous on purpose: it exists to catch a hung process, not a slow one. A run that hits it is stopped and fails.

Cancellation and Failure

Cancel cancels the batch's Swift task. FFmpegProcess turns that into SIGTERM for the running ffmpeg and reports a cancellation. The subtlety is that FFmpeg catches SIGTERM and exits normally with status 255, the same as many real failures, so the process runner records whether it sent the signal itself before it decides what an exit means. Without that, a crashed encode could read as a cancel and quietly stop the whole batch, or a cancel could read as an error.

Any exit other than success — non-zero status, crash, timeout, cancel — deletes the partly written output, so a failed row never leaves a truncated file beside the source. A non-zero exit fails with FFmpeg's last three lines of stderr, which is usually the sentence that says what went wrong.

The Queue

Adding

Dropped URLs and the open panel's selection go through one path, ContentViewModel.add. A folder is enumerated recursively, skipping hidden files, filtered and sorted by path. A file is accepted when the uniform type for its extension conforms to public.audio, public.movie or public.audiovisual-content — the same three types the open panel allows — and is not already in the queue.

Converting

Convert takes a snapshot of the format, its preset and the destination folder, then walks the waiting rows in order, awaiting each conversion before starting the next. One at a time is deliberate: an encode already uses the CPU well, a batch finishes in the order it was queued, and a failure is attributed to one file. Rows added during a run are not part of it; they wait for the next Convert.

Naming

ArgumentBuilder.uniqueOutputURL takes the source's name without its extension, adds the format's extension, and if that path exists tries name 2, name 3… until one is free. The check covers the source itself, so converting talk.mp3 to MP3 beside its source writes talk 2.mp3. The destination is chosen when that file's turn comes, so two sources with the same name in one batch also get distinct outputs.

Busy

While a batch runs, the window registers itself in BatchActivity, a weak set of owners with work under way. The self-updater asks it before relaunching (below). It holds owners weakly, so a window that closed mid-run cannot block an update for the rest of the session.

Settings Storage

TranscoderSettings — the chosen format, a Preset per format, and the output folder path — is encoded as JSON and kept under one key, TranscoderSettings, in the app's defaults domain, io.github.sevmorris.Transcoder. It is written on every change. A format with no saved preset uses Preset.defaults(for:); a preset field left empty means Same as source.

The app reaches its defaults through UserDefaults.app, never .standard. When the binary is hosting the unit tests, AppLauncher starts it with no window and no update check, and UserDefaults.app is a scratch suite in the temporary folder, so a test run never reads or writes the real settings.

Self-Update

UpdateChecker asks the GitHub API for sevmorris/Transcoder's latest release and compares its tag numerically with the running version. At launch the check is silent unless there is something to install; from the Help menu it always reports.

Every release's notes end with an HTML comment, <!-- minimum-macos: 15.0 -->, written by release.sh from the built app's LSMinimumSystemVersion. A release that needs a newer macOS than the Mac has is not offered: installing it would replace a working app with one that will not open.

Installing is SelfUpdater.swift, shared verbatim by every app in the family:

  1. DownloadThe release's DMG, with progress. It can be cancelled.
  2. Check the imageThe disk image's signature is verified before it is mounted: it must be signed by Developer ID team T9RLNAXPWU. An unsigned image is never parsed by hdiutil.
  3. Check the appThe image must hold exactly one app at its top level, signed by the same team, with the running app's bundle identifier, a newer version, this Mac's architecture and a minimum macOS this Mac meets. It is copied out, its signature checked again, and the image detached.
  4. Wait for workIf BatchActivity says a conversion is running, the update waits, then asks before relaunching, since a relaunch would clear the finished queue from the screen.
  5. Swap and relaunchThe new app replaces the old in one atomic renamex_np(RENAME_SWAP), from the app's own process, and the app relaunches. macOS lets an app replace one signed by its own team without the App Management permission.

Any failure leaves the installed app as it was and offers the DMG in the browser instead. So does a copy that cannot replace itself: a development build, one running from a disk image or translocated by Gatekeeper, or one the user cannot write. There is no update feed and no signing key beyond the Developer ID: trust is the team and the bundle identifier.

The Bundled FFmpeg

The app carries its own ffmpeg and ffprobe in Contents/Resources, and runs only those, never one on the PATH. A conversion therefore behaves the same on every Mac, whatever Homebrew has installed.

How It Is Built

scripts/build-ffmpeg.sh builds all three from their release archives, statically, for arm64 and the app's macOS 15.0 floor. It is FilmStrip's audio-only recipe, r5, with libopus added. Configure runs with --disable-autodetect, so nothing on the build machine leaks in, and without --enable-gpl, --enable-nonfree or --enable-version3, so the result stays LGPL 2.1-or-later. The script asserts the result: both encoders present, no non-system dynamic libraries, the right minimum macOS, and an LC_UUID, without which dyld on recent macOS refuses to run an executable.

The build is reproducible — ZERO_AR_DATE=1, a fixed build path, -ffp-contract=off — so two runs produce identical binaries, and anyone can rebuild and compare checksums.

How It Gets Into the App

The binaries are not committed. They are published as a pre-release on the repository, ffmpeg-deps-9.0.2-audio-opus-arm64-r5, and Vendor/ffmpeg-manifest.env pins that release and the SHA-256 of each binary. scripts/fetch-ffmpeg.sh downloads and verifies them; Xcode runs it as a build phase, and release.sh and CI run it before building as well. Deps releases stay pre-releases so the app's own release remains /releases/latest, and superseded ones are never deleted, since older commits verify against them.

LGPL Obligations

FFmpeg runs as a separate executable that Transcoder launches; nothing from it is linked into the app. The corresponding source is the upstream archives named, with their URLs, in the manifest, plus the build script that turns them into the shipped binaries. Anyone may rebuild them, modify them, and replace the copies inside the app bundle.

Generations and Headroom

A lossy encoder decides what a listener will not miss and discards it. Run the result through another lossy encoder and it makes the same kind of decision again, on audio that already carries the first encoder's artefacts — and different encoders discard different things, so the losses add up rather than overlap. Each generation is a little worse. Practical consequences:

  • 1Convert from the best source you have. A WAV or FLAC master to AAC beats an MP3 of it to AAC at any bitrate.
  • 2Lossless to lossless is exact. WAV, AIFF, FLAC and Apple Lossless can be converted among each other any number of times without change, provided the bit depth and sample rate are kept (or raised).
  • 3Lossy to lossless preserves the lossy file exactly, and only that: the result is larger, not better. It is useful when a tool demands WAV.
  • 4Lossy to lossy, if you must, at a generous bitrate: the second encoder should not have to squeeze.
  • 5Raising the sample rate or bit depth adds no information. Lowering them is a real reduction: 24 to 16 bits reduces dynamic range from about 144 dB to about 96 dB, and 96 to 44.1 kHz removes everything above about 22 kHz.

Decoders produce floating-point audio and FFmpeg converts it to the output's sample format. A lossy source that was loud to begin with can decode to peaks slightly above full scale, which an integer output then clips; 32-bit float WAV is the one output that keeps them.

Command Reference

For a tagged MP3 with a JPEG cover, converted to 24-bit FLAC at 48 kHz, Transcoder runs:

ffprobe -v error -show_format -show_streams -of json "talk.mp3"

ffmpeg -hide_banner -nostdin -y -i "talk.mp3" \
  -progress /tmp/transcoder-progress-….txt -nostats \
  -map 0:0 -map 0:1 \
  -map_metadata 0 -map_chapters -1 \
  -c:a flac -sample_fmt s32 -bits_per_raw_sample 24 \
  -ar 48000 \
  -c:v copy -disposition:v:0 attached_pic \
  "talk.flac"

The same file to Opus at the default bitrate drops the cover, which the Ogg muxer cannot hold:

ffmpeg -hide_banner -nostdin -y -i "talk.mp3" \
  -progress /tmp/transcoder-progress-….txt -nostats \
  -map 0:0 \
  -map_metadata 0 -map_chapters -1 \
  -c:a libopus -b:a 128k \
  -ar 48000 \
  -f opus \
  "talk.opus"

ArgumentBuilderTests checks each part of these command lines — encoders, bitrates, sample formats, rates, mapping, artwork, naming — without running FFmpeg, and ConversionTests runs the bundled FFmpeg end to end: a tagged sample with a cover, converted to all seven formats, each output probed for its codec, its tags and, where the container holds one, its artwork.
